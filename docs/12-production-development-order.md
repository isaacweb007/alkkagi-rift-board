# 알까기 실제 게임 개발 순서

## 원칙

화려한 캐릭터와 토큰 경제보다 먼저 `같은 입력은 같은 결과를 만들고, 한 경기가 중단 없이 끝나는가`를 확정한다. 물리 결과가 안정되지 않으면 네트워크 동기화, 랭크, 포인트 원장도 신뢰할 수 없다.

## 0단계 — 플레이 코어 고정

현재 착수 및 1차 완료 단계다.

- 3:3·5:5, 20초 배치, 랜덤 선공, 20초 턴, 보너스 샷 규칙 고정
- 추진·중량·내구·정밀·회전의 물리 변환식 고정
- 120Hz 고정 스텝 물리
- 충돌, 마찰, 회전, 링아웃, 동시 최종 추락 판정 모듈 분리
- 브라우저 렌더링과 무관한 결정론 테스트 작성
- AI를 상대로 배치부터 승패까지 한 경기 실행

완료 기준: 자동 물리 테스트 통과, WebGL 오류 없음, 3:3·5:5 경기 진입과 AI 턴 작동.

## 1단계 — 경기 상태와 리플레이

- 경기 시드, 초기 배치, 모든 샷 입력을 이벤트 로그로 저장
- 현재 프레임 전체를 저장하지 않고 `stoneId, direction, power, spin, sequence`만 기록
- 이벤트 로그만으로 같은 경기를 다시 재생
- 일시 정지, 재시작, 재접속용 스냅샷 생성
- 클라이언트가 임의로 승패와 보상을 선언하지 못하도록 결과 API 분리

완료 기준: 저장된 입력 로그를 세 번 재생해 모든 돌의 최종 위치와 승자가 동일함.

## 2단계 — 실제 3D 자산 파이프라인

- Blender GLB 캐릭터 3종과 아레나 1종을 먼저 제작
- 기본·조준·발사·충돌·가장자리 공포·추락 표정 상태
- PBR 텍스처, LOD 3단계, Draco/KTX2 압축
- 캐릭터 데이터와 모델·음성·VFX 프리셋 연결
- 저사양에서 그림자·파티클 자동 축소

완료 기준: 최초 경기 로딩 15MB 이하, 일반 PC 60fps, 저사양 30fps 이상.

## 3단계 — 서버 권위 실시간 대전

- 경기 하나당 Durable Object 하나 배정
- WebSocket으로 배치·샷 입력·스냅샷 교환
- 서버가 공유 물리 코어로 링아웃·턴·보너스 샷·승자를 계산
- 클라이언트 예측과 서버 보정
- 150ms 지연, 패킷 손실, 재접속, 턴 시간 초과 처리
- LV ±2 자동 매칭과 대기 시간 확장

완료 기준: 서로 다른 두 브라우저의 3:3 경기가 끝까지 동기화되고 새로고침 후 복구됨.

## 4단계 — 계정·성장·상점

- 계정 프로필, 출전 덱, 캐릭터 보유 목록
- XP·레벨·연습 AI 해금
- 능력치 총예산을 유지하는 업그레이드와 무료 재분배 검증
- 외형 스킨·표정·음성·추락 효과 상점
- 서버 결과만 테스트 Play Point 원장에 반영

완료 기준: 결제나 토큰 없이도 게임 진행·획득·성장 루프가 재미있고 공정함.

## 5단계 — 라이브 운영과 보안

- 리플레이 기반 신고·관전자·부정행위 분석
- 매치메이킹 지표, 이탈률, 캐릭터 승률, 샷 분포
- 시즌, 랭크, 보상, 패치 데이터 원격 설정
- 부하 테스트, 오류 추적, 롤백, 콘텐츠 버전 호환

## 6단계 — Web3 검토 게이트

현금성 토큰은 게임 완성과 별개의 출시 게이트다.

- 국가별 법률·등급분류·도박성·경품 규정 검토
- KYC/AML, 미성년자 보호, 지역 제한
- 스마트컨트랙트와 지갑 보안 감사
- 봇·담합·다중 계정·경기 조작 방지
- 출금 한도, 수수료, 세금, 고객지원과 사고 대응

위 조건을 통과하기 전에는 출금 불가능한 테스트 Play Point만 사용한다.

## 이번 작업에서 실제 시작한 코드

- `app/arena/core.ts`: 렌더링과 분리된 공용 경기 물리·턴 규칙
- `tests/physics-core.test.ts`: 발사·마찰·회전·충돌·링아웃·턴·승패 테스트
- `app/arena/engine.ts`: 공용 코어를 사용하는 Three.js/WebGL 경기 실행기
- 브라우저 확인: 3D 캔버스, 3:3 배치, 배치 확정, AI 샷, 보너스 샷, 오류 없음 확인
