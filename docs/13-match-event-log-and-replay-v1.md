# 경기 이벤트 로그·3D 리플레이 V1

## 이번 단계의 목표

연습 경기 한 판을 단순한 화면 결과가 아니라 **다시 실행할 수 있는 데이터**로 남긴다. 이 데이터 포맷은 즉시 3D 다시보기에 사용하며, 이후 서버 권위형 PvP의 재접속 스냅샷과 판정 감사 로그로 확장한다.

## 기록하는 이벤트

- 포맷 버전, 경기 ID, 3:3/5:5, 아레나, AI 레벨
- 랜덤으로 결정된 선공 주체
- 배치 종료 시 모든 돌의 ID와 X/Z 좌표
- 각 샷의 순번, 공격 주체, 돌 ID, 정규화된 방향, 파워, 회전값
- 최종 승자와 경기 생성 시각

캐릭터 능력치와 물리 상수는 현재 빌드의 고정 로스터·공유 물리 코어를 사용한다. 포맷 `version: 1`이므로 향후 로스터나 물리 규칙이 바뀌면 버전별 재생기를 유지하거나 마이그레이션해야 한다.

## 실행 흐름

1. 경기 시작과 동시에 빈 이벤트 로그를 만든다.
2. 20초 배치가 확정되면 양 팀 돌 좌표를 캡처한다.
3. 플레이어와 AI가 발사할 때마다 동일한 샷 이벤트를 순서대로 기록한다.
4. 승패가 결정되면 브라우저 로컬 저장소와 D1에 최근 경기를 저장한다.
5. 로비의 `MATCH ARCHIVE`에서 마지막 경기를 선택하면 배치 좌표를 복원하고 모든 샷을 3D 고정 스텝 물리로 재실행한다.

## 서버 API와 보관 정책

- `GET /api/game/replay`: 현재 계정 또는 게스트의 가장 최근 유효 리플레이 반환
- `POST /api/game/replay`: 구조·범위·소유권·순번을 검증한 뒤 저장
- D1 `match_replays`: 사용자별 최근 10건 유지
- 최대 200샷, 100KB 요청 제한
- 돌 ID 위조, 공격 주체 불일치, 중복 배치, 좌표 범위 초과, 잘못된 파워·회전은 거부

리플레이 데이터는 현재 클라이언트가 보고하므로 **승패 보상이나 현금성 가치의 권위 자료가 아니다**. 보상은 별도 결과 영수증으로 중복 지급을 막고 있으며, 네트워크 PvP 단계에서는 서버 시뮬레이션이 이벤트와 결과를 모두 확정해야 한다.

## 재접속으로 확장할 때 추가할 것

- 서버가 서명한 규칙/로스터 빌드 버전
- 현재 턴, 남은 시간, 살아 있는 돌과 속도, 이벤트 커서
- 클라이언트 마지막 확인 이벤트 번호와 재전송 규칙
- 주기적 상태 해시와 불일치 교정 스냅샷
- 경기 종료 전 임시 이벤트 스트림과 만료 정책

- 전체 빌드와 HTML 구조 테스트 6개
- 로컬 D1 저장/조회/잘못된 요청 400 응답 확인
