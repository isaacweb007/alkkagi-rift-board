# HTML5 엔진·네트워크 아키텍처 V1

## 현재 결과물의 정의

`concept-site/public/play/index.html`은 설치 없이 PC 브라우저에서 실행하는 플레이 가능한 버티컬 슬라이스다. Canvas 2D 위에 3D풍 캐릭터·조명·아레나를 합성하고, 고정 시간 간격 물리와 Web Audio를 사용한다. 3:3과 5:5의 핵심 손맛을 먼저 검증하며, 실시간 두 플레이어 동기화와 현금성 토큰은 아직 출시 기능으로 간주하지 않는다.

## 확정 경기 규칙

1. 매치 유형은 3:3 속전과 5:5 정규전이다.
2. 양쪽은 경기 시작 전 20초 동안 자기 반원 안에서 돌의 위치를 정한다.
3. 서버가 선공을 50:50으로 무작위 결정한다.
4. 자기 턴에는 살아 있는 돌 하나를 선택하고 반대 방향으로 당긴다.
5. 당긴 거리로 파워 0–100을 정하고, `Shift`와 휠로 미세 조절하며 `Q/E`로 회전을 준다.
6. 모든 돌이 정지한 뒤 상대 돌이 떨어졌으면 같은 플레이어가 보너스 샷을 얻는다.
7. 상대 돌을 전부 떨어뜨린 플레이어가 승리한다.

```text
LOBBY → MATCHMAKING → PLACEMENT(20s) → RANDOM FIRST ATTACK
      → AIM → RELEASE → RESOLVE PHYSICS → RING-OUT?
          ├─ YES: BONUS SHOT 또는 승리
          └─ NO: TURN SWAP
      → RESULT → XP/LEVEL/PLAY POINT UPDATE
```

## HTML5 물리 엔진

- 논리 해상도: 1600×900, CSS로 화면에 맞춰 축소한다.
- 시뮬레이션: 렌더 프레임과 분리된 120Hz 고정 스텝이다.
- 충돌: 원–원 충돌 법선, 중량 기반 임펄스, 위치 보정으로 겹침을 해결한다.
- 감속: 보드 마찰을 매 스텝 적용하고 임계 속도 아래에서 완전히 정지시킨다.
- 추락: 돌 중심이 안전 반경을 넘으면 링아웃 상태로 전환한다.
- 회전: 돌의 진행 방향에 수직인 힘을 짧게 가해 커브를 만든다.
- 결정성 목표: 같은 초기 상태와 입력은 같은 결과를 내도록 난수는 경기 시작 시드에만 둔다. 현재 세로 슬라이스는 로컬 시뮬레이션이며 서버 버전에서 정수/고정소수점 계산으로 강화한다.

## 5개 능력치의 실제 효과

| 능력치 | 엔진 반영 | 플레이 감각 |
|---|---|---|
| 추진 | 같은 파워에서 초기 속도 증가 | 강한 직선 공격 |
| 중량 | 충돌 질량과 반동 저항 증가 | 몸싸움·밀어내기 |
| 내구 | 충돌 후 속도 보존과 감쇠 저항 | 연쇄 충돌 지속 |
| 정밀 | 예상선 길이·조준 안정성 증가 | 얇은 맞히기 |
| 회전 | 커브 계수와 측면 제어 증가 | 우회·뱅크 플레이 |

랭크 공정성을 위해 업그레이드는 총 능력치 예산을 늘리는 방식보다 분배를 바꾸는 방식이 우선이다. 유료 외형은 물리에 영향을 주지 않는다.

## 원소 타격과 귀여운 추락

- 불: 주황 충격파, 불꽃 파편, 낮은 폭발음.
- 물: 청록 링과 방울 입자, 짧은 물방울 음.
- 번개: 갈라지는 선과 백색 플래시, 고역 클릭.
- 천둥: 카메라 흔들림과 굵은 저역 타격.
- 공허: 보라색 흡입 링과 역재생형 음색.
- 추락: 캐릭터별 음높이로 0.6–1.1초 내려가는 비언어 비명 뒤 작은 `뿅` 구조음을 낸다.

광과민 접근성을 위해 `prefers-reduced-motion`에서는 플래시와 이동 애니메이션을 크게 줄이며, 사운드는 항상 끌 수 있다.

## 지옥 AI 연습장

연습은 3:3·5:5를 모두 제공한다. 적은 잿불아귀, 폭뢰뿔, 심연눈, 사슬간수, 지옥강아지로 구성된다. AI 레벨 1–10에 따라 조준 오차, 파워 선택, 가장자리 표적 우선순위가 달라진다. 승리하면 다음 연습 레벨이 열리며, 패배해도 소량 XP를 지급해 학습이 막히지 않게 한다.

## 프로필과 레벨 매칭

Cloudflare D1의 `players`, `match_queue`, `matches` 테이블이 프로필과 매칭 티켓을 저장한다.

- 서버 프로필: 레벨, 현재 레벨 XP, 테스트 Play Point, 승패, 연습 해금 단계.
- 매칭: 같은 3:3/5:5 모드에서 우선 `LV ±2`를 찾고 레벨 차이와 대기 시간 순으로 고른다.
- 선공: 매치 생성 시 서버가 무작위로 한 명을 지정한다.
- 게스트: 브라우저 UUID로 시작하고, 배포 환경의 ChatGPT 인증 헤더가 있으면 계정 해시 ID를 쓴다.

현재 결과 API는 세로 슬라이스 검증을 위한 클라이언트 보고 방식이므로 `verified: false`와 `sandbox_play_points`를 명시한다. 이 포인트는 출금·환전·거래할 수 없다.

## 실시간 네트워크 출시를 위한 다음 게이트

진짜 랭크 대전에서는 브라우저가 승패나 보상을 선언하면 안 된다. 다음 단계는 아래 순서로 구현한다.

1. 서버가 경기 시드, 배치 제한, 20초 마감, 턴과 입력 시퀀스를 소유한다.
2. 클라이언트는 `stoneId`, 단위 방향 벡터, 파워, 회전만 보낸다.
3. Durable Object 한 개가 한 경기를 담당해 고정소수점 물리를 시뮬레이션한다.
4. 서버 스냅샷을 10–20Hz로 전송하고 브라우저는 보간·예측한다.
5. 서버만 링아웃, 보너스 샷, 승자, XP와 포인트 원장을 확정한다.
6. 재접속, 입력 재전송, 턴 타임아웃, 비정상 속도·연속 요청 차단을 검증한다.
7. 봇 부하, 지연 150ms, 패킷 손실, 동시 접속 테스트를 통과한 뒤 랭크 표기를 연다.

## Web3와 현금성 토큰 경계

승자가 상대의 참가 포인트를 얻는 구조는 국가별 도박·경품·게임산업·자금세탁 규제, 미성년자 보호, KYC/AML, 세금, 지갑 보안 검토가 필요하다. 따라서 현재 버전은 현금 가치가 없는 Play Point만 사용한다. `$1 토큰` 입출금은 법률 의견, 등급분류, 경제 시뮬레이션, 스마트컨트랙트 감사, 부정행위 방지, 지역 차단을 모두 통과한 별도 서비스 단계로 둔다.
